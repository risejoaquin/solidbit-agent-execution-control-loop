## 🔒 Security Architecture: Zero-Unauthorized-Deploy Guardrails

SACL operates under the principle of **Hard Deny Supremacy**:
- **Autonomous Agent Containment:** Autonomous agent processes (e.g. `agy.exe`, Claude, Gemini) are restricted to ephemeral Git worktrees (`wt-*`).
- **No Direct Cloud Mutations:** Agents have **zero direct credentials** to execute unreviewed changes against production cloud infrastructure (Railway, Supabase, Vercel).
- **HMAC-SHA256 Cryptographic Tokens:** Every production or staging deployment requires an out-of-band, cryptographically signed approval token generated by the Sovereign Authority (`@risejoaquin`).
- **SQLite WAL Compare-And-Swap:** Job transitions are guarded against race conditions and lock-stealing using atomic CAS statements.

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability within SACL:

1. **Do NOT report security vulnerabilities via public GitHub issues.**
2. Send an encrypted email or report directly to the Sovereign Authority:
   - **Primary Contact:** Joaquín Vallejo ([@risejoaquin](https://github.com/risejoaquin))
   - **Email:** `security@solidbit.dev`
3. Please include:
   - Description of the vulnerability and attack vector.
   - Exact steps to reproduce or proof-of-concept (PoC).
   - Potential impact on frozen contracts (`DR-INV-001`, `DR-PAY-001`).

### Vulnerability Response SLA
- **Initial Acknowledgement:** Within 24 hours.
- **Triage & Threat Assessment:** Within 48 hours.
- **Fix & Advisory Release:** Critical vulnerabilities are addressed within 7 business days under responsible disclosure.
